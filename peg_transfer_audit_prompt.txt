Tasks:

1. Map the project structure.
   - Identify the files and directories relevant to robotic surgery, dVRK, Peg Transfer, reinforcement learning, training, evaluation, logging, and checkpoints.
   - Distinguish active code from obsolete, duplicated, experimental, or unused code where possible.

2. Identify the Peg Transfer environment/task entry point.
   - Trace the execution path from the command used to start training down to the environment/task implementation.
   - Identify configuration files and dependencies involved.

3. Reconstruct the observation space.
   For every observation:
   - name
   - source in code
   - dimensions
   - reference frame
   - normalization/scaling
   - clipping
   - noise/randomization
   - whether it is privileged information
   - whether it is available during inference

4. Reconstruct the action space and control mode.
   Determine:
   - action dimensions
   - joint-space vs Cartesian control
   - position/velocity/torque targets
   - scaling
   - clipping
   - action rate
   - smoothing
   - actuator/controller implementation
   - mapping from policy outputs to the dVRK joints/end-effector

5. Audit the reward function.
   List EVERY reward term and for each one report:
   - mathematical meaning
   - implementation location
   - weight/scale
   - activation conditions
   - sign
   - expected magnitude
   - whether it is dense or sparse
   - which phase of Peg Transfer it encourages
   - possible conflicts with other rewards

   Reconstruct the approximate total reward equation.

   - timeouts

   - workspace violations
   - grasp loss
   - collisions
   - joint limits
   - success criteria
   - episode initialization/randomization

7. Audit the PPO pipeline.
   Identify:
   - algorithm implementation/library
   - network architecture
   - actor/critic inputs
   - learning rate
   - batch/minibatch sizes
   - rollout length
   - number of environments
   - gamma
   - lambda/GAE
   - clipping
   - entropy coefficient
   - value loss coefficient
   - gradient clipping
   - normalization
   - scheduler
   - checkpointing
   - evaluation
   - curriculum
   - domain randomization

8. Inspect existing training and evaluation outputs.
   Search for:
   - logs
   - TensorBoard data
   - CSV files
   - checkpoints
   - videos
   - evaluation scripts
   - success metrics
   - reward component histories
   - previous experiments

   Summarize what has already been tried.

9. Diagnose why the current policies are failing.
   Separate clearly:
   A. facts directly supported by code/logs
   B. hypotheses
   C. missing evidence required to validate each hypothesis

   Look specifically for:
   - reward hacking
   - badly scaled reward components
   - insufficient exploration
   - impossible or noisy observations
   - poor action scaling
   - unstable control
   - sparse-reward bottlenecks
   - premature termination
   - curriculum discontinuities
   - environment reset bugs

    - define exact code/config changes
